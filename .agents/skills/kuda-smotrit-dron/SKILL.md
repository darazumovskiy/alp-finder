# Куда смотрит дрон (разбор ракурса по скриншоту)

Вход: скриншот плеера (имя видео в заголовке окна + таймкод на UI).
Выход в чат: сводка + два изображения из `analysis/fullframe/rakursy/`.
Рабочий python — только `analysis/.venv/bin/python` с `PYTHONPATH=analysis`.

## 1. Атрибуция

- Имя видео — из заголовка плеера (`DJI_YYYYMMDDHHMMSS_NNNN_Z.MP4`). Файл искать:
  `ls data/drive/<дата>/*/`, `rg <токен> scripts/manifest.tsv` (папки дней зовутся
  по-разному: `dron/`, `drone/`).
- Таймкод: левая цифра — текущее время → `t` в секундах. Правая цифра бывает
  **и длительностью, и оставшимся временем** — сверить с
  `ffprobe -v error -show_entries format=duration -of default=nw=1 <видео>`
  и позицией ползунка в процентах.
- Телеметрия — сайдкар `<видео>.MP4.gps.tsv`; нет — сгенерировать
  `scripts/dji_meta_gps.py`.

## 2. Верификация кадра

Извлечь кадр и сравнить глазами со скриншотом (обязательно, до всех расчётов):

```bash
ffmpeg -v error -ss <t> -i <видео> -frames:v 1 -q:v 2 /tmp/check.jpg -y
```

Не совпал — развёртка ±10 с шагом 2 с, при разметке на скрине — SIFT-матч
(скилл `tochka-na-kartu-po-foto`, шаг 3).

## 3. Разбор ракурса

```bash
PYTHONPATH=analysis analysis/.venv/bin/python analysis/view_footprint.py <видео> <t>
```

Печатает: позицию/высоту дрона, yaw/pitch подвеса, точку и дистанцию центра
кадра, диапазон охвата по периметру, положение опорных точек (в кадре /
за кромкой с пикселем / вне оси). Пишет `<имя>_t<T>_annotated.jpg` (кадр со
стрелками на находки) и `<имя>_t<T>_map.png` (схема: дрон, полигон охвата,
находки) в `analysis/fullframe/rakursy/`.

- Фокусное берётся из `analysis/coverage/<имя>.coverage.tsv`; там пусто —
  оценить `analysis/geoproject.py focal <видео> T0 T1` и передать `--f`.
  Центральный луч от фокусного не зависит — грубого значения хватает.
- Список опорных точек — `TARGETS` в `analysis/view_footprint.py`,
  синхронизирован с `docs/nakhodki/README.md`; изменились координаты — править там.
- GSD и «объект в 8 пикс» на момент t — готовые в той же coverage-таблице.

## 4. Интерпретация (в ответ пользователю)

- Дрон: координаты, абсолютная высота, **двигался или висел** — смотреть трек
  вокруг t, а не предполагать по кадру: смена картинки чаще всего — поворот
  гимбала из той же точки висения.
- Камера: компасный азимут (`yaw % 360`), наклон (pitch > 0 — вверх, в кадре
  склон над дроном).
- Что в кадре: точка центра (координаты, высота рельефа, дистанция), охват
  мин–макс, масштаб (GSD).
- Находки: для каждой — в кадре / сразу за кромкой (сколько градусов не
  хватило) / далеко вне оси; дистанция.
- Сверка с контекстом: близость точки центра к плановому треку
  (`docs/marshrut/README.md`), существующие карточки этого видео на карте
  (`rg <имя-видео> analysis/viewer/build_map.py`) — ракурс может уже быть
  кандидатом.

## Ловушки

- Луч полого к склону: вилку DEM и предупреждение печатает
  `analysis/geoproject.py cast <видео> <t> 960 540 <f>` — прогнать его для
  центра, если точка важна; при вилке > 30 м координату центра давать с
  оговоркой «нижняя оценка, кромка может быть выше».
- Pitch выше горизонта — центр в рельеф не попадает, описывать сектор
  направлением и лучами периметра, попавшими в склон.
- На стене района вещей GLO-30 врёт до ~58 м (`docs/dem-patches.md`).
- Скилл ничего не публикует: карта, POINTS, реестр не трогаются. Найден
  кандидат — передать пользователю, точку вносит скилл `tochka-na-kartu-po-foto`.
