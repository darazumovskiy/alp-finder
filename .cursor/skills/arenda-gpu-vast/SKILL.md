# Аренда GPU (vast.ai): платные прогоны без выжигания бюджета

Каждый час арендованной машины — деньги оператора. Ошибка, найденная после
запуска, оплачена. Отсюда все правила ниже; они не обсуждаются.

## Железные правила

0. **Денежные операции — только с явного аппрува оператора.** Пополнение
   баланса, аренда, любое списание: оператор либо делает сам, либо явно
   аппрувит данную конкретную операцию с озвученной суммой. Биллинг
   агенту не выдаётся by design; наличие API-ключа — не аппрув.
1. **Верификация перед КАЖДЫМ платным прогоном — только скиллом
   `verifikatsiya-platnogo-progona`** (рой саб-агентов с запечёнными
   промптами на чистом контексте: концепция решения, математика его
   реализации, стоимость; у каждого вердикта — оценка уверенности).
   Проверяется РЕШЕНИЕ, которое считаем/тренируем, а не логистика аренды.
   Писать промпты проверяющим самому ЗАПРЕЩЕНО. Любая ошибка чинится,
   рой перезапускается целиком.
2. **Объяснение оператору перед стартом** — простыми словами, от простого
   к сложному: что будет делаться, как, сколько это будет стоить
   (вилка и потолок), что получим на выходе; плюс сводка вердиктов роя.
   Старт — только после «да».
3. **Стоп-лимит.** Смета озвучена до аренды. Факт превысил прогноз
   в 1,5 раза — остановить очередь и доложить, не досчитывать молча.
4. **Смоук первых минут.** После запуска убедиться, что первая задача
   реально считает: `nvidia-smi` показывает загрузку карт, лог растёт.
   Только потом оставлять без присмотра, дальше — периодический контроль.
5. **Скачивание до гашения.** Результаты скачаны к нам и проверены
   (размер, читаемость) → только после этого сказать оператору гасить
   инстанс — и напомнить сделать это СРАЗУ: простой тоже тарифицируется.
6. **Приватность.** На сервер уезжает минимум необходимых данных.
   Инстанс приватный, под нашим ключом; после скачивания результатов
   уничтожается вместе с данными. Никаких публичных шар и ссылок.

## SSH

Выделенный ключ `~/.ssh/id_ed25519_vast` (рабочие ключи на чужие серверы
не ходят). Публичная половина загружена в аккаунт vast.ai
(Keys → SSH Keys) и автоматически попадает в новые инстансы.
Подключение — командой со вкладки Instances:
`ssh -p PORT root@sshN.vast.ai -i ~/.ssh/id_ed25519_vast`.

Перед любой работой с vast.ai прочитать

## Выбор машины (чеклист аренды)

- фильтр запроса ЦЕЛИКОМ: `verified=true reliability>0.98
  cuda_vers>=<CUDA образа> direct_port_count>=1 duration>=1 rentable=true`
  + диск + канал; CUDA образа смотреть в конфиге образа через Docker Hub
  registry API (не гадать);
- `cpu_cores_effective` ≥ нужного (это НАША доля; `cpu_cores` — вся машина);
- цена = ЭФФЕКТИВНАЯ: dph + storage_cost×диск + (inet_up_cost+inet_down_cost)×трафик;
- брать ТОП-3 оффера как очередь ретраев (офферы уводят);
- диск ≥ 2× пика данных (диск НЕ расширяется после создания);
- для COLMAP PatchMatch — не Blackwell (5090): известный баг пустых карт;
- смета = часы × эффективная цена, озвучить оператору до аренды;
- новую технику отлаживать на самом дешёвом однокарточном хосте
  ($0.03–0.06/час), дорогой брать после зелёного end-to-end.

## Процедура прогона (проверена end-to-end 20.08)

1. Верификация роем (правило 1) → объяснение, сводка вердиктов и «да»
   оператора (правило 2, включая аппрув сумм по правилу 0).
2. Создание — ключ кладёт НАШ onstart (агент хоста ломается молча):
   `vastai create instance <OFFER> --image <IMG> --disk N --ssh --direct
   --onstart-cmd 'env >> /etc/environment; mkdir -p /root/.ssh && chmod 700
   /root/.ssh && echo "<PUB>" >> /root/.ssh/authorized_keys && chmod 600
   /root/.ssh/authorized_keys; echo "export LD_LIBRARY_PATH=/usr/lib/x86_64-linux-gnu:$LD_LIBRARY_PATH"
   > /etc/profile.d/cudafix.sh; echo ONSTART_OK'`
   (cudafix глушит forward-compat ловушку CUDA на GeForce).
3. Поллинг статуса С ТАЙМАУТОМ 15 мин и веткой ошибок: `exited`/`unknown`/
   `offline` НИКОГДА не станут running → `destroy -y` → следующий оффер.
4. `vastai logs <ID>` → ждать `ONSTART_OK` (проверка ключа БЕЗ ssh).
   Нет маркера при running > 5 мин → битый хост → destroy → следующий.
5. SSH строго по `vastai ssh-url` (не по show instances), ретраи 3 мин
   («Connection refused» первые 30–60 с — норма); denied > 5 мин при
   ONSTART_OK → destroy → следующий оффер.
6. Смоук ≤ 3 мин, гейты ТОЛЬКО на exit-code (не на строки вывода):
   nvidia-smi; nproc (сверка с cpu_cores_effective); `ldconfig -p | grep
   libcuda` (обязан резолвиться НЕ из /usr/local/cuda/compat/); реальное
   CUDA-ядро (для COLMAP: feature_extractor на 2 кадрах). Провал по вине
   хоста → report + destroy, НЕ чинить чужой хост.
7. Заливка: rsync только по direct-порту (прокси душится > 1 ГБ);
   `vastai copy` сломан (issue #326) — не использовать.
8. Тест-кусок → скачивание → локальное чтение → рендер → показ оператору →
   его «годно» → полная очередь.
9. Очередь: `nohup bash <скрипт> … >> /workspace/job.log 2>&1 &` (`>>`:
   рестарт не затирает лог). Через 2–3 мин проверить: GPU загружены, лог
   растёт. Один экземпляр очереди одновременно.
10. Каждые 20–30 мин: `vastai logs` + rsync ГОТОВЫХ результатов к нам
    (хост может умереть без предупреждения и без рефанда) +
    `vastai show invoices-v1 --charges` (контроль расхода).
11. Гашение: НИКОГДА не stop (диск биллится вечно, GPU уводят) — только
    `destroy -y`, и только после exit-code финального rsync и локального
    чтения файлов. После — `vastai show instances` пуст.
12. Страховки от забытой машины: локальный таймер destroy + при желании
    самостоп изнутри (`timeout Nh задача; vastai stop instance
    $CONTAINER_ID` — ключ `$CONTAINER_API_KEY` предустановлен).

## Прогон плотной фотограмметрии зон (текущая задача проекта)

Данные: `analysis/scene3d/data/<зона>/dense/` (готовит
`analysis/scene3d/prep_dense.py`). Очередь на машине:
`analysis/scene3d/run_dense_all.sh <каталог_зон> <число_GPU>` —
идемпотентна, зона целиком на одной карте, выход `fused.ply` на зону.
После скачивания: геопривязка → поверхность+орто → вставка в «Полёт 3D»
(`analysis/scene3d_insert.py`, референс — модель вещей 19.08).
