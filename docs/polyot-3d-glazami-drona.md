# Полёт 3D: режим «глазами дрона» — как устроен (передача контекста)

дальнейшее развитие режима ведётся отдельной сессией. Реконструкция сцены

## Что это

Галка «глазами дрона — кадр у трека» в панели «Фото со съёмки» страницы
polyot-3d.html (включение из ссылки — `#eye`, вместе с обоями — `#photo,eye`).
Настоящие кадры съёмки проецируются на воксельный рельеф из поз дрона,
в которых они были сняты. Рядом с позой параллакс мал — кадр ложится на
рельеф почти без искажений, «смотри, что видел дрон отсюда».

## Данные: слой eye в payload

`analysis/viewer/build_polyot3d.py`, функция `eye_layer()`:
на флайт `dict(v=имя_ролика, s=[[i, x, z, yb, yaw, pitch, f1024]…])`, где

- `i` — номер кадра кеша плеера `flights/<v>/f%04d.jpg` (кадры 1024×576,
  шаг 5 с, режет `analysis/flight_cache.py`);
- `x, z` — позиция в блоках сетки движка (8 м), `yb` — высота в тех же
  единицах: `(alt − zmin)/BX`;
- `yaw` — компасный азимут подвеса (0=север, по часовой), `pitch` —
  наклон (минус вниз), градусы;
- `f1024` — фокусное в пикселях кадра шириной 1024
  (= фокусное coverage tsv × 1024/1920).

Поза интерполируется по сэмплам `flights/<v>/meta.json` (шаг 2 с, yaw — с
развёрткой через 360°), фокусное — ближайшее из
`analysis/coverage/<video>.coverage.tsv` (±6 c). Кадры без фокусного
пропускаются. Сейчас 2118 поз по 80 полётам, ~100 КБ в payload.

## Рантайм: полёт3d_template.html, блок «глазами дрона»

Искать по `EYE_R` / `eyeUpdate` / `eyeApply`. Архитектура:

- **6 проекторов одновременно** (`EYE_N=6`). Каждый слот: поза `e`,
  текстура кадра (юниты TEXTURE3..8), вес `w`, целевой вес `tgt`,
  дистанция до прицела `d`.
- **Выбор кадров — по дистанции поза↔ПРИЦЕЛ** (переделано 18.08): якорь —
  точка, куда смотрит пользователь (`lookAt()`, марш взгляда до рельефа).
  Навёл камеру на гору — связка переезжает на гору; смотришь под ноги —
  кадры вокруг тебя. Радиус подбора `EYE_R=150` блоков (1.2 км) от прицела,
  вес `0.96·(1−d/EYE_R)^0.5`. История: v1 выбирала по направлению взгляда
  с ratio-гистерезисом — моргала; v2 только по дистанции камера↔поза —
  замерзала (см. ниже) и не показывала гору, на которую смотришь.
- **Гистерезис — в метрах, не в отношении оценок**: новый кадр вытесняет
  худший слот, только если он ближе к прицелу на `EYE_MARG=25` блоков
  (~200 м). Старое правило «score ×1.3» на пологой кривой `^0.30` было
  математически недостижимо — связка замерзала навечно («кадры зависают»).
- **Разнос связки**: кандидат ближе `EYE_SEP=12` блоков (~100 м) к уже
  показанной позе пропускается — 6 кадров покрывают склон, а не одну точку
  трека (раньше связка могла состоять из соседних кадров одного пролёта).
- **Изинг весов**: `sl.w += (target−sl.w)·min(1, dt·3)`; пока анимация не
  сошлась — `dirty=true` (у движка ленивая перерисовка, без этого кроссфейд
  замирает). Кадр не показывается, пока его jpg не догрузился (`sl.ok`).
- **Шейдер**: `eyeApply(mat4, sampler, w, c, worldPos)` — проецирует мировую
  точку в клип-пространство дрона; внутри кадра берёт пиксель, вес умножается
  на затухание к краям кадра (smoothstep 0.80→1.0). Слоты применяются по
  возрастанию веса — сильнейший рисуется последним и перекрывает.
- **Матрица дрона** (`eyeMatrix`): позиция (x, yb, z); направление
  `[sin(yaw)·cosP, sin(pitch), −cos(yaw)·cosP]` (сетка: x — восток, z — юг,
  y — вверх); проекция `persp(2·atan(288/f1024), 1024/576, 0.5, 14000)`,
  дальше `mul(persp, view)` — хелперы движка. Проверка корректности: точка
  в 100 м вдоль оси взгляда обязана попадать в ndc (0,0) — тест был пройден
  численно, скрипт-однострочник восстановим из истории сессии либо заново.
- HUD: `#eye-note` — главный кадр, дистанция до позы, вес, размер связки.

## Ограничения (физика, не баги)

- Кадр честен ТОЛЬКО около своей позы: дальше — параллакс, картинка «плывёт»
  по рельефу (поэтому вес тает с дистанцией). Показ всех 2118 кадров сразу
  невозможен и бессмыслен — перекроют друг друга.
- Заслонение не учитывается: кадр проецируется и на рельеф, который дрон
  не видел (за гребнем). Рядом с позой почти незаметно; лечится depth-map
  от позы дрона (второй проход) — не делалось.
- Швы яркости между кадрами разных роликов — экспонирование не выравнивается.
- Кадры 1024 px — при сильном приближении мыло; полные 1920 достанутся
  только декодом из видео (в кеше плеера их нет).

## Идеи следующего шага (обсуждались, не делались)

- Выравнивание экспозиции кадров в связке (по перекрытию).
- Depth-тест от позы дрона против воксельного рельефа (убрать протекание
  через гребни).
- Приоритет кадров с лучшим GSD, а не только ближних.
- Клавиша «сесть в позу дрона»: телепорт камеры в ближайшую позу с её
  yaw/pitch — идеальное совпадение кадра с рельефом по построению.

## Отладка (секция «Отладка» в панели, добавлена 18.08)

Оператор жмёт «⏺ запись» — на экране появляется таймер REC (попадает на
скриншоты), в лог каждые 0.5 с пишутся камера/прицел/слоты (только при
изменениях) и события: назначение кадра в слот, отказ гистерезиса («отбор
стоп: кандидат … не ближе худшего»), загрузка jpg, гашение слота, щелчки
галок. Поле комментария (Enter), кнопки «копировать лог»/«скачать».
Оператор присылает лог + скриншоты — по T+времени они связываются.
Искать по `DBG`/`dbgSample`. Хеш `#dbgrec` — авто-старт записи (смоук-тесты).
Заодно: keydown-обработчик теперь игнорирует набор в INPUT/TEXTAREA
(раньше буквы в поиске точек гоняли камеру).
