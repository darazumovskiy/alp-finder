# Полёт 3D: режим «глазами дрона» — как устроен (передача контекста)

дальнейшее развитие режима ведётся отдельной сессией. Реконструкция сцены

## Что это

Галка «глазами дрона — кадр у трека» в панели «Фото со съёмки» страницы
polyot-3d.html (включение из ссылки — `#eye`, вместе с обоями — `#photo,eye`).
Настоящие кадры съёмки проецируются на воксельный рельеф из поз дрона,
в которых они были сняты. Рядом с позой параллакс мал — кадр ложится на
рельеф почти без искажений, «смотри, что видел дрон отсюда».

## Данные: слой eye в payload

`analysis/viewer/build_polyot3d.py`, функция `eye_layer()`: на флайт
`dict(v=имя_ролика, s=[[i, x, z, yb, yaw, pitch, f1024, fx, fz, fyb, fd]…])`, где

- `i` — номер кадра кеша плеера `flights/<v>/f%04d.jpg` (кадры 1024×576,
  шаг 5 с, режет `analysis/flight_cache.py`);
- `x, z` — позиция в блоках сетки движка (8 м), `yb` — высота в тех же
  единицах: `(alt − zmin)/BX`;
- `yaw` — компасный азимут подвеса (0=север, по часовой), `pitch` —
  наклон (минус вниз), градусы;
- `f1024` — фокусное в пикселях кадра шириной 1024
  (= фокусное coverage tsv × 1024/1920);
- `fx, fz, fyb` — ТОЧКА СЪЁМКИ (18.08): куда упёрся луч оси камеры в рельеф
  (марш по сетке высот при сборке), в блоках; `fd` — длина луча в блоках,
  мера детальности (чем короче, тем крупнее снят объект). Кадры, чей луч
  не упирается в рельеф ближе 2.5 км (горизонт/небо), выбрасываются.

Поза интерполируется по сэмплам `flights/<v>/meta.json` (шаг 2 с, yaw — с
развёрткой через 360°), фокусное — ближайшее из
`analysis/coverage/<video>.coverage.tsv` (±6 c). Кадры без фокусного
пропускаются. Сейчас 2105 поз по 80 полётам, ~130 КБ в payload.

## Рантайм: полёт3d_template.html, блок «глазами дрона»

Искать по `EYE_R` / `eyeUpdate` / `eyeApply`. Архитектура:

- **12 проекторов одновременно** (`EYE_N=12`, юниты TEXTURE3..14; в шейдере
  uEyeVP0..11 / uEyeT0..11 / веса uEyeWa,Wb,Wc). Каждый слот: поза `e`,
  текстура, вес `w`, целевой вес `tgt`, ранг `d`, дистанция прицел↔съёмка `df`.
- **Выбор кадров — по ТОЧКЕ СЪЁМКИ, а не по позе дрона** (v4, 18.08): кадр
  оценивается по близости его точки съёмки (fx/fz/fy) к якорям: «покажи
  кадры, которые СНИМАЛИ то, что я вижу». Ранг = дистанция + `0.25·fd` —
  штраф дальней съёмки: детальный кадр вытесняет мыльный дальний с того же
  места. Радиус `EYE_R=150` блоков, вес `0.96·(1−df/EYE_R)^0.5`.
- **Якоря — сетка 3×3 по полю зрения** (v5, 18.08, `eyeAnchors`): лучи через
  центр и 8 точек экрана марш-ем до рельефа (дедуп 30 блоков); дистанция
  кадра — до ближайшего якоря. Иначе вся связка липла к перекрестью:
  «в прицеле кадр хороший, вокруг пустота».
- **Пятно кадра** (v5): проекция гасится за пределами радиуса `r` вокруг
  точки съёмки (`r = clamp(2.2·fd·512/f, 10, 80)` блоков, смузстеп r→1.8r,
  uEyeC0..11 в шейдере). Без этого кадр «протекал» на касательный дальний
  рельеф размазнёй (жалобы «хрень», «глюк-вкрапление»).
  История: v1 — по направлению взгляда, моргала; v2 — по дистанции
  камера↔поза с ratio-гистерезисом ×1.3, замерзала навечно (порог
  недостижим на пологой кривой); v3 — поза↔прицел: кадры выбирались, но
  светили не туда — поза рядом не значит, что камера снимала это место
  (лог оператора 18.08: слоты w=0.9, рельеф голый).
- **Разрешение по подлёту** (v6): штраф конфетти умножается на
  `covK=clamp(cd/50, 0.1, 3)`, где `cd` — дистанция камеры до ближайшего
  якоря: издалека слоты достаются широким кадрам (площадь), при подлёте —
  детальным зум-кадрам («подъехал ближе — получи выше разрешение»).
  Разнос связки тоже сжимается вблизи: `sep=clamp(cd/8, 3, 12)` блоков.
- **Гистерезис — в метрах**: новый кадр вытесняет худший слот, только если
  его ранг лучше на `EYE_MARG=25` блоков (~200 м).
- **Разнос связки**: кандидат, чья точка съёмки ближе `EYE_SEP=12` блоков
  (~100 м) к уже показанной, пропускается — 12 кадров покрывают площадь,
  а не дублируют одну точку.
- **Обои НЕ включаются автоматически** — оператор считает слой сырым
  (тормозит, артефакты); «глазами дрона» живёт сам по себе.
- **Изинг весов**: `sl.w += (target−sl.w)·min(1, dt·3)`; пока анимация не
  сошлась — `dirty=true` (у движка ленивая перерисовка, без этого кроссфейд
  замирает). Кадр не показывается, пока его jpg не догрузился (`sl.ok`).
- **Шейдер**: `eyeApply(mat4, sampler, w, c, worldPos)` — проецирует мировую
  точку в клип-пространство дрона; внутри кадра берёт пиксель, вес умножается
  на затухание к краям кадра (smoothstep 0.80→1.0). Слоты применяются по
  возрастанию веса — сильнейший рисуется последним и перекрывает.
- **Матрица дрона** (`eyeMatrix`): позиция (x, yb, z); направление
  `[sin(yaw)·cosP, sin(pitch), −cos(yaw)·cosP]` (сетка: x — восток, z — юг,
  y — вверх); проекция `persp(2·atan(288/f1024), 1024/576, 0.5, 14000)`,
  дальше `mul(persp, view)` — хелперы движка. Проверка корректности: точка
  в 100 м вдоль оси взгляда обязана попадать в ndc (0,0) — тест был пройден
  численно, скрипт-однострочник восстановим из истории сессии либо заново.
- HUD: `#eye-note` — главный кадр, дистанция до позы, вес, размер связки.

## Удалено по вердикту оператора (18.08, поздняя сессия)

- **Обои (ортомозаика)** — «тормозят и показывают лажу»: слой, галка
  `L-photo`, весь ORTHO-код и шейдерная ветка uPhoto вырезаны из
  polyot-3d.html. Тайлы `ortho/` в dist ОСТАЮТСЯ — их использует map.html.
- **Запечённый фон** (build_eye_bake.py, eyebake/) — «туфта»: был офлайн-бейк
  всех кадров в текстуру 3 м/пикс; удалён вместе со скриптом (восстановим из
  git-истории, коммит 860ea87, если понадобится).

Остался только режим «глазами дрона» (вердикт: «работает сносно») + G.
Клавиша G — «сесть в глаза дрона»: телепорт в позу съёмки лучшего кадра у
прицела (совпадение идеально по построению), повторное G — следующий кадр.
Подписи в меню сокращены («не бомби длиннющими подписями»).

## Ограничения (физика, не баги)

- Кадр честен ТОЛЬКО около своей позы: дальше — параллакс, картинка «плывёт»
  по рельефу (поэтому вес тает с дистанцией). Показ всех 2118 кадров сразу
  невозможен и бессмыслен — перекроют друг друга.
- Заслонение не учитывается: кадр проецируется и на рельеф, который дрон
  не видел (за гребнем). Рядом с позой почти незаметно; лечится depth-map
  от позы дрона (второй проход) — не делалось.
- Швы яркости между кадрами разных роликов — экспонирование не выравнивается.
- Кадры 1024 px — при сильном приближении мыло; полные 1920 достанутся
  только декодом из видео (в кеше плеера их нет).

## Отладка (секция «Отладка» в панели, добавлена 18.08)

Оператор жмёт «⏺ запись» — на экране появляется таймер REC (попадает на
скриншоты), в лог каждые 0.5 с пишутся камера/прицел/слоты (только при
изменениях) и события: назначение кадра в слот, отказ гистерезиса («отбор
стоп: кандидат … не ближе худшего»), загрузка jpg, гашение слота, щелчки
галок. Поле комментария (Enter), кнопки «копировать лог»/«скачать».
Оператор присылает лог + скриншоты — по T+времени они связываются.
Секция — ПЕРВАЯ в меню слоёв (внизу её прятала панель подсказок #help —
теперь у #layers max-height с запасом под неё). Искать по `DBG`/`dbgSample`.
Хеш `#dbgrec` — авто-старт записи (смоук-тесты).
Заодно про фокус (жалоба «после меню клавиши полёта не работают»):
keydown игнорирует только ТЕКСТОВЫЕ поля; галки/селекты/слайдеры/кнопки
блюрятся после использования; mousedown по канвасу снимает фокус руками
(его preventDefault не даёт браузеру сделать это самому).
