# Приём новых видео

Конвейер: обнаружение → докачка → телеметрия → сканы (цвет + следы) →
ИИ-отсмотр → показ каждого кандидата в чат + отчёт → слои покрытия. Справка по
устройству слоёв конвейера — `docs/video-analysis.md`.
Рабочий python — `analysis/.venv/bin/python`.

**Находки этим скиллом на карту и в реестр НЕ вносятся — никогда, ни при какой
уверенности.** Итог — показ кандидатов человеку в чате (раздел 6) и отчёт.
Внесение точки — скилл `tochka-na-kartu-po-foto` и только после явного
подтверждения человека по конкретному кандидату; «предложить и внести» в один
ход запрещено.

## 1. Обнаружение новых файлов

Источника два, проверять оба (Яндекс бывает раньше Google):

- Google Drive — gdrive MCP, `gdrive_list_files` корня
  `1uD9uCzOm9e2GdKYiOO2Jp3GVvE8Cn3XX`, затем по `folder_id` папки новой даты
  (имена подпапок бывают с хвостовым пробелом).
- Яндекс-зеркало — публичный API без авторизации:

```bash
curl -sS "https://cloud-api.yandex.net/v1/disk/public/resources?public_key=https%3A%2F%2Fdisk.yandex.ru%2Fd%2FzyqqUfN8A-iQzg&limit=200"
# подпапка: добавить &path=%2F14.08.2026
```

## 2. Манифест, опись, докачка

- `scripts/manifest.tsv`: строка `путь \t drive_file_id \t размер_байт`;
  файл есть только на Яндексе — id-плейсхолдер `YADISK` (качает
  `download_yadisk.py` по имени+размеру; появится на Google — проставить id).
- `docs/drive-inventory.md`: раздел новой даты (что снято, есть ли SRT),
  обновить «Итого» и «Обновлено».
- Докачка — сначала Яндекс, потом Google (уже скачанное пропускается по размеру):

```bash
python3 scripts/download_yadisk.py; bash scripts/download_drive.sh
```

Разовый обрыв SSL у Яндекс CDN лечится повторным запуском. Финальная
проверка — скрипты сами сверяют размеры с манифестом.

## 3. Телеметрия

SRT есть не у всех роликов; рабочий источник — сайдкары из встроенного потока:

```bash
analysis/.venv/bin/python scripts/dji_meta_gps.py data/drive/<дата>/<папка>/*.MP4
```

Проверка: `head -2` сайдкара + быстрый разбор геометрии полёта (bbox координат,
высоты, тангаж, дистанции до опорных точек реестра) — он же даёт контекст
«что снимал дрон» для промптов отсмотра. У JPG в XMP — дальномер
`LRFTargetLat/Lon/AbsAlt/Distance` (координаты **объекта**, не дрона) —
извлекать regex по `drone-dji:<Key>="…"`.

## 4. Сканы: цветовой детектор + слой следов

Цветовой (предметы):

```bash
for v in <список basename>; do
  analysis/.venv/bin/python analysis/video_scan.py "data/drive/<дата>/<папка>/$v.MP4" --out "analysis/scans/$v"
done; echo SCAN_ALL_DONE
```

Слой следов (борозды, дорожки вмятин — цветовой их не ловит), для роликов
**с телеметрией**:

```bash
for v in <список basename>; do
  analysis/.venv/bin/python analysis/furrow_scan.py "data/drive/<дата>/<папка>/$v.MP4" --out "analysis/scans-furrow/$v"
done; echo FURROW_ALL_DONE
```

Гребневой отклик с прайором «вниз по склону» (телеметрия + DEM); топ-10
вытянутых компонент на кадр, трекинг повторов, выход того же формата.
Главный ложняк топа — кромки снежников и потёки. Ролики **без телеметрии**
(вертолёт): слой не работает — следы ищутся VLM-отсмотром полных кадров,
отобранных `analysis/trace_frames.py` (дедуп по сдвигу сцены, CLAHE;
с телеметрией он же режет по участку `--lat0/--lat1/--lon0/--lon1`).

Фон — только средствами тула (`block_until_ms: 0`, ждать sentinel);
`nohup … &` умирает вместе с shell-сессией. Быстро: ~11 мин видео за
десятки секунд (цвет) / ~3 мин (следы). Выход `analysis/scans/<видео>/` и
`analysis/scans-furrow/<видео>/`: `tracks.tsv` (track, таймкоды, bbox,
score, GPS **дрона**), `crops/tNNNN_MMmSSs.jpg`, `montage_NN.jpg`.

## 5. ИИ-отсмотр

- Норматив — минимум топ-4 монтажных листа (~144 трека) на ролик.
- Параллельные сабагенты (`generalPurpose`, фон), **не больше 4 листов на
  сабагента** — на большем падают. Промпт: контекст операции, геометрия
  полёта из шага 3, список известных вещей («помечай как известное»), профиль
  ложных срабатываний (охристые/бирюзовые камни, лишайник, наледь, тени,
  блики), пути к montage/crops/tracks.tsv, запрет записи файлов, формат
  ответа — таблица «трек | таймкод | что вижу | известное/новое | ув. 1–5».
- Монтажи слоя следов (`scans-furrow`) и кадры `trace_frames` — отдельными
  батчами тех же сабагентов; промпт про следы: борозды/дорожки вмятин/воронки,
  эталоны — `analysis/fullframe/gennadiy-124655/g3_t244_grooves.png` и
  `data/telegram/novye-skrinshoty/1752.jpg`, ложняки — потёки (ветвятся),
  слоистость фирна (по всей ширине), кромки снежников, борозды камнепада
  (камень в конце дорожки).
- Ключевых кандидатов сабагентов перепроверять своими глазами по кропам,
  при нужде — кадр исходника: `ffmpeg -ss $t -i <видео> -frames:v 1 -vf "crop=…" out.jpg`.
  JPG-фото идут мимо детектора — отсматривать самому.
- Хвосты треков (ниже топ-144) — по цветовым сигнатурам:

```bash
cd analysis && .venv/bin/python rank_by_signature.py scans/<видео>/tracks.tsv --out scans/<видео>/ranked.tsv --верх 3
```

  Отбор: `расстояние <= 1.0` и ближе к вещи, чем к ловушке; из отобранных —
  временные монтажи (cv2, сетка 6×6) и те же сабагенты порциями ≤4 листа.
- Грабли: Glob не видит `analysis/scans/*/crops/` — только `ls` с глобами
  (`ls | rg` может виснуть); полный отчёт сабагента — из его JSONL в
  `agent-transcripts/<parent>/subagents/` (самый длинный text-блок).

## 6. Отчёт и передача человеку

- **Каждый кандидат ув. ≥3 показывается в чате отдельным блоком** — не списком,
  не только файлами. Блок строго из трёх частей:
  1. полный кадр с тонкой красной обводкой (эллипс/линия, 2 px);
  2. крупный кроп того же объекта;
  3. мета: имя файла видео и таймкод `M:SS`; координата с названием ступени
     лестницы и σ — либо честное «координаты нет, ступень не пройдена»;
     GSD и размер объекта с указанием, чем меряли; положение относительно
     ближайшего объекта реестра; ув. 1–5; чем ещё это может быть.
  Отчёт, записанный в файл и не показанный в чате, результатом не считается.
  Кандидаты ув. 2 и ниже — списком в отчёте, в чат не выносить.
- `analysis/review/<дата>.md`: происхождение данных; таблица «куда летал дрон»
  (видео | время | позиция | тангаж | что снимал); кандидаты с ув. 1–5
  (слабые ув. 2 отдельно); хвосты по сигнатурам; «что дальше».
  Плюс строка в `docs/video-analysis.md` (диапазон дат + ссылка + резюме дня).
- Для человека: пары `*_full.jpg` (полный кадр с обводкой) +
  `*_crop.jpg` в `analysis/review/findings-<дата>/`; координаты (LRF для
  фото — но НЕ для SUPR-тайлов: там лазер смотрит по сетке панорамы, не на
  объект; конус взгляда для видео; для кандидатов слоя следов — трассировка
  луча через пиксель кандидата с вилками, `geoproject.py cast`). Кандидат
  на панорамном тайле, пологом луче (<~15°) или у кромки — координата только
  по лестнице скилла `tochka-na-kartu-po-foto` (`analysis/triangulate.py`
  `find`/`solve`); собственные модели поверхности («стена через якорь» и т.п.)
  не изобретать — ошибка ~100 м (случай 15.08). Размеры —
  только SIFT-цепочкой масштабов от JPG с дальномером (каждое звено
  ≥20 инлаеров, валидация на предметах известного размера); «якорная»
  оценка с допущением неизменного зума ошибается в разы.
- Публикации наружу (TG и т.п.) — только по прямой просьбе и после
  независимой проверки.

## 7. Слои покрытия и плеер «Полёт»

При появлении новых видео обновить обязательно:

```bash
cd analysis
.venv/bin/python coverage_gsd.py --dates <YYYYMMDD,…>   # GSD-таблицы новых дат, минуты
.venv/bin/python coverage_map.py                        # сетка всего района, секунды
.venv/bin/python flight_cache.py --all                  # кеш плеера «Полёт», досчитывает только новое
.venv/bin/python slope_sample.py                        # сэмплы «склон срыва» из кешей, секунды
.venv/bin/python viewer/build_map.py                    # карта (подхватывает полёты и сэмплы)
```

Кеш плеера — кадры раз в 5 с + мета (позиция, углы, полигон охвата) в
`analysis/viewer/flights/<ролик>/`; ролики без телеметрии или без полей
подвеса пропускаются с пометкой. Запускать после coverage_gsd (фокусное
для полигонов берётся из coverage-таблиц) и до build_map. `slope_sample.py`
пересобирает из кешей сэмплы плеера (`viewer/flights/samples/*.json`,
описание — docs/video-analysis.md «Сэмплы плеера») и печатает дыры
покрытия полосы срыва — упомянуть их в отчёте дня.

Входы — все сайдкары `data/drive/**/*.MP4.gps.tsv` и таблицы
`analysis/coverage/<видео>.coverage.tsv`; выход —
`analysis/coverage/coverage-map-cells.json`, слои «Осмотр: …» в `map.html`.
Уровни по лучшему различимому предмету (порог 8 px): detail ≤ 20 см,
mid ≤ 1 м, over — остальное/масштаб неизвестен; слои вложенные
(detail ⊂ mid ⊂ over). Проверить в браузере (локальный :8077, чекбоксы,
ползунок плотности), при изменениях логики — независимое ревью сабагентом
на свежем контексте до публикации.

## 8. Деплой

Только по явной просьбе пользователя («публикуй»):

```bash
analysis/.venv/bin/python analysis/viewer/build_dist.py
npx wrangler pages deploy analysis/viewer/dist --project-name alp-finder
bash scripts/deploy_mirror.sh    # git push в gh-pages — тоже требует явной просьбы
curl -sL https://alp-finder.pages.dev/map | rg -c "<маркер>"
curl -sL "https://darazumovskiy.github.io/alp-finder/map.html?nocache=$(date +%s)" | rg -c "<маркер>"
```

GitHub Pages пересобирается 1–2 минуты; `*.pages.dev` из РФ-сети блокируется —
проверять по зеркалу.
