# alp-finder

Поисково-аналитический проект: помощь штабу поисковой операции на пике Курумды (Кыргызстан) в отсмотре съёмок с дрона и вертолёта. Три альпиниста пропали при спуске после восхождения 2 августа 2026. Задача проекта — алгоритмическая предобработка десятков часов видео и выявление подозрительных кадров (люди, снаряжение, следы, палатки, верёвки) для передачи координат штабу; с 27.08 — также мониторинг снега на склоне к третьему этапу поисков.

**Это не учебный проект. От скорости и качества работы может зависеть жизнь людей.** Любая находка перепроверяется перед передачей штабу; ложные срабатывания тратят ресурс спасателей, пропущенные кадры — хуже.

**Статус: поисковая операция завершена (25.09.2026).** Автоматический мониторинг снега остановлен (launchd-агент выгружен), режим приватности снят, ветка `team-only` влита в `main`, репозиторий и сайт открыты. Проект — архив и справочник; новые данные не ожидаются.

Этот файл и `CLAUDE.md` — зеркальные копии (один для Cursor, другой для Claude Code); менять оба одновременно. Локальные, не входящие в git инструкции (`CLAUDE.local.md`, `docs/*.local.md`) имеют приоритет над этим файлом.

## Точки входа: скиллы

Скиллы лежат в двух копиях: `.cursor/skills/<имя>/` (Cursor) и `.claude/skills/<имя>/` (Claude Code, вызов `/<имя>`).

- **priyom-novykh-video** — приём новых видео съёмки: закачка с Drive/Яндекс, телеметрия, сканы (цвет + слой следов), ИИ-отсмотр, показ каждого кандидата в чате, отчёт, слои покрытия и кеш плеера «Полёт». На карту и в реестр не вносит — только после явного подтверждения человека. Когда: «появились новые видео», «обнови покрытие».
- **tochka-na-kartu-po-foto** — добавление находки на карту по фото/скриншоту: атрибуция видео и таймкода, SIFT-сверка кадра, координаты из телеметрии, карточка в реестр, пересборка и деплой. Когда: волонтёр или оператор приносит кандидата.
- **kuda-smotrit-dron** — разбор ракурса дрона по скриншоту: где дрон, куда смотрит, что видит, какие находки в кадре (инструмент `analysis/view_footprint.py`); на карту не вносит. Когда: аналитика ракурсов, проверка геометрии.
- Только в `.cursor/skills/`: **arenda-gpu-vast** (аренда GPU для плотной фотограмметрии) и **verifikatsiya-platnogo-progona** (проверка платного прогона перед оплатой).

## Мониторинг снега и осадков (с 27.08.2026)

Задача штаба: следить «с дивана» (спутники, метеомодели, станции; дроны/датчики/люди на горе исключены), снега на склоне стало больше или меньше, по высотам, и накопить историю к 15.09.2026.

- **Справочник реализации — [docs/osadki-monitoring/realizatsiya.md](docs/osadki-monitoring/realizatsiya.md)**: что где лежит, поток данных, шаги конвейера, индекс снега v2, ИИ-агент, запуск руками, расписание, отладка, публикация, что в git. Читать первым при любой работе с `analysis/osadki/`.
- База знаний — [docs/osadki-monitoring.md](docs/osadki-monitoring.md): рисерч источников (§1–6, отчёты в `docs/osadki-monitoring/otchety/`), уточнённый интент штаба (§7), аудиты методики, индекс v2, конвейер, агент (§8; аудиты — `docs/osadki-monitoring/audit/`).
- Код — `analysis/osadki/`: `run_daily.py` (конвейер, 13 шагов), `snow_index.py` (индекс v2), `agent_daily.py` (ИИ-оценка, **только `claude-fable-5`**), `build_report.py` → `analysis/viewer/osadki-monitoring.html`, `build_sverka.py` → `sverka-avgust-2026.html`; рукописный журнал `analysis/osadki/fakt-vs-model.tsv`; заметки агента `analysis/osadki/agent/notes/`.
- Расписание — было: launchd `com.alp-finder.osadki` (`scripts/osadki_daily.sh`, `scripts/com.alp-finder.osadki.plist`), 08:00 и 18:00 по Бишкеку; каждый запуск виден на странице. **Остановлено 25.09.2026** (операция завершена), последний прогон — 25.09 18:02 по Бишкеку; запуск руками по-прежнему возможен.
- Решения оператора: только Fable 5 без запасных моделей; все числа с погрешностью, выводы с уровнем доверия; на странице явно различать алгоритмический расчёт (шаблон) и сгенерированный текст агента; оценка агента лежит на дне снимка Sentinel-2; методику проверять независимыми сабагентами на чистом контексте; в TG пока не слать.

## Данные

- Источник: общая папка Drive `1uD9uCzOm9e2GdKYiOO2Jp3GVvE8Cn3XX` (папки по датам). Доступ на чтение — публичный и через gdrive-коннектор.
- Локальное зеркало наполняется скриптом: `bash scripts/download_drive.sh` — качает по `scripts/manifest.tsv`, уже скачанные файлы (совпал размер) пропускает. При появлении новых файлов на Drive: обновить опись в `docs/drive-inventory.md`, дописать строки в манифест, перезапустить скрипт.
- SRT-файлы рядом с видео — телеметрия DJI: GPS, высота, параметры камеры на каждый кадр. Использовать для геопривязки кадров.
- Папки «Покадровый просмотр» на Drive (кадры, нарезанные волонтёрами) не скачиваются: кадры извлекаем сами из исходников; их разметка полезна как референс калибровки.
- Второй источник — Telegram-группа волонтёров «Анализ видео с дронам» (темы: новые скриншоты, гипотезы, подтверждённые/отклонённые кандидаты, инструкции). Выгрузка: `python scripts/tg_export.py` после разового логина (`--login`, нужны TG_API_ID/TG_API_HASH с my.telegram.org). Инструкция волонтёрам по отсмотру — `docs/viewing-instructions.md` (копия в базе TG: `docs/telegram/instrukcii-i-ssylki/2026-08-12-instrukciya-prosmotra.md`), «отклонённые» — готовый набор ложных срабатываний для калибровки.
- Мониторинг снега: Sentinel-2 (AWS earth-search, без ключей), Sentinel-1 RTC (Planetary Computer), VIIRS (NASA GIBS), Open-Meteo (ECMWF IFS + вилка моделей + ансамбль), OGIMET (станции Каракуль, Сары-Таш). Детали — docs/osadki-monitoring/realizatsiya.md §4.

## Правила работы

- ЗАПРЕЩЕНО общаться с оператором квиз-формами (AskQuestion / AskUserQuestion и любые формы с вариантами ответов). Все вопросы — обычным текстом в чате.
- Сначала инвентаризация и документирование, потом обработка: каждое видео должно иметь запись в описи (что снято, какой участок, есть ли телеметрия).
- Все выводы рисерчей фиксировать в `docs/` — проект рассчитан на много сессий, контекст живёт в файлах, не в чате. Для людей (штаб, волонтёры) — отдельные понятные HTML-отчёты на сайте (`analysis/viewer/otchety.html` — список), md в `docs/` — база для агентов.
- Кандидаты-находки оформлять с точной ссылкой: файл, таймкод, координаты кадра, скриншот, степень уверенности.
- Любая находка перепроверяется перед передачей штабу. Методики (координаты, индекс снега, модели) проверять независимым аудитором на чистом контексте с установкой искать ошибки; аудиты класть в `docs/`.
- Ключи и пароли (Anthropic, TG, воркер) — только в локальных файлах и окружении; в транскрипты, логи и коммиты не попадают.
- Внешние PR (GitHub, волонтёр C C — он же автор расчётов General #1641/#1659 в TG) перед мержем проверять на наших данных: телеметрию — сверкой с волонтёрскими SRT (`data/telegram/general/1141.zip`), координаты — по записям дальномера в JPG (`LRFTarget*` в XMP).
