# alp-finder

Поисково-аналитический проект: помощь штабу поисковой операции на пике Курумды (Кыргызстан) в отсмотре съёмок с дрона и вертолёта. Три альпиниста пропали при спуске после восхождения 2 августа 2026. Задача проекта — алгоритмическая предобработка десятков часов видео и выявление подозрительных кадров (люди, снаряжение, следы, палатки, верёвки) для передачи координат штабу.

**Это не учебный проект. От скорости и качества работы может зависеть жизнь людей.** Любая находка перепроверяется перед передачей штабу; ложные срабатывания тратят ресурс спасателей, пропущенные кадры — хуже.

## Контекст операции

Подробности: `docs/operation-context.md`. Ключевое:

- Район: пик Курумды (6096 м), Чон-Алайский хребет, восточнее пика Ленина.
- Критичный неосмотренный участок: между лагерями 2 и 3.
- Штаб выкладывает съёмку в общий Google Drive, контакты штаба в `docs/operation-context.md`.

## Данные

- Источник: общая папка Drive `1uD9uCzOm9e2GdKYiOO2Jp3GVvE8Cn3XX` (папки по датам). Доступ на чтение — публичный и через gdrive-коннектор.
- Локальное зеркало наполняется скриптом: `bash scripts/download_drive.sh` — качает по `scripts/manifest.tsv`, уже скачанные файлы (совпал размер) пропускает. При появлении новых файлов на Drive: обновить опись в `docs/drive-inventory.md`, дописать строки в манифест, перезапустить скрипт.
- SRT-файлы рядом с видео — телеметрия DJI: GPS, высота, параметры камеры на каждый кадр. Использовать для геопривязки кадров.
- Папки «Покадровый просмотр» на Drive (кадры, нарезанные волонтёрами) не скачиваются: кадры извлекаем сами из исходников; их разметка полезна как референс калибровки.
- Второй источник — Telegram-группа волонтёров «Анализ видео с дронам» (темы: новые скриншоты, гипотезы, подтверждённые/отклонённые кандидаты, инструкции). Выгрузка: `python scripts/tg_export.py` после разового логина (`--login`, нужны TG_API_ID/TG_API_HASH с my.telegram.org). Инструкция волонтёрам по отсмотру — `docs/viewing-instructions.md` (копия в базе TG: `docs/telegram/instrukcii-i-ssylki/2026-08-12-instrukciya-prosmotra.md`), «отклонённые» — готовый набор ложных срабатываний для калибровки.

## Правила работы

- Сначала инвентаризация и документирование, потом обработка: каждое видео должно иметь запись в описи (что снято, какой участок, есть ли телеметрия).
- Все выводы рисерчей фиксировать в `docs/` — проект рассчитан на много сессий, контекст живёт в файлах, не в чате.
- Кандидаты-находки оформлять с точной ссылкой: файл, таймкод, координаты кадра, скриншот, степень уверенности.
- Внешние PR (GitHub, волонтёр C C — он же автор расчётов General #1641/#1659 в TG) перед мержем проверять на наших данных: телеметрию — сверкой с волонтёрскими SRT (`data/telegram/general/1141.zip`), координаты — по записям дальномера в JPG (`LRFTarget*` в XMP). Влиты PR #1 (телеметрия с углами подвеса), #2 (`docs/nezavisimyy-analiz/`), #3 (`docs/avalanche-assessment.md` + `search_vectors.kml`), #4 (методика фокусного — только документ, код внешний), #5 (цветовые сигнатуры), #6 (стенд врезок `analysis/inject_probe.py`), #10 (запрос на облёт + оранжевый кандидат в `docs/nezavisimyy-analiz/`), #12 (3D-модель участка: `analysis/scene3d/` + `docs/nezavisimyy-analiz/model-3d/`).
